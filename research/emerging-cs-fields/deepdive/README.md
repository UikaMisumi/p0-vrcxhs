## 2. 各方向最值得做的 3 个问题（偏学术组）

**可验证代码**（详见 [vericoding.md §6](vericoding.md)）
1. 自动评估规约是否忠实于需求：没有标准答案时，用可执行规约、对抗输入和变异测试来打分。算力低，难度中。
2. 检测空洞规约和作弊证明（`assume`、`sorry`、过弱的后置条件），并审计现有基准。已有工作在 VERINA 中发现 23 条为假的规约。算力低。
3. 仓库级的依赖感知检索和引理库，以及基于真实 commit 历史的证明修复基准。算力低–中。

**进化搜索**（详见 [evolutionary_search.md §6](evolutionary_search.md)）
1. 严谨的评测方法：在同等预算下比较、跑多个随机种子，权衡更多种子还是更多迭代。arXiv 2609.19799《Evolution or Illusion?》发现，方法之间的排名会随预算翻转。算力低–中。
2. 不容易被钻空子的评估器：随机化或隐藏测试、形式规约，以及专门衡量框架作弊倾向的基准。算力低。
3. 为新领域构建评估器（编译器、数据库、网络协议、生物信息等）。一个好的评估器加上现成框架，往往就够一篇论文。算力低–中。

**持续学习 / TTT**（详见 [continual_ttt.md §6](continual_ttt.md)）
1. 公平评测协议：在同等算力、延迟和存储下，比较 TTT 与长上下文、RAG、多次采样，并用真实的、带时间戳的新知识构造基准。算力低。
2. 遗忘的机制：比较 SFT、RL 和 on-policy 蒸馏，解决"RL's Razor"与"RL Forgets!"之间的证据冲突。算力低–中。
3. 稀疏或局部化写入的参数化记忆：把 Sparse Memory Finetuning 扩展到 LoRA 或 MoE 专家。算力中。

**智能体基础设施**（详见 [agent_infra.md §6](agent_infra.md)）
1. 开放的多场景智能体 trace 集和回放模拟器。现有的负载刻画几乎都来自编码智能体。算力低。
2. 对外部副作用（网络、数据库、SaaS 调用）的事务和回滚语义，即把经典 OS/DB 技术用到新场景。算力低，难度高。
3. 沙箱与 GPU 推理的协同调度：工具调用期间 KV cache 是保留、卸载还是丢弃，以及沙箱的预热与放置。单机即可做。

## 3. 交叉机会：四个方向的共同问题

单独看每个方向会漏掉一点：4 份报告里排名靠前的研究机会，有好几个本质上是同一个问题。

| 共同问题 | 出现在 | 含义 |
|---|---|---|
| **验证器和评估器本身是否可信** | 可验证代码 #2，进化搜索 #3，进化搜索中的奖励作弊 | 一套"评估器审计"方法（空洞性检测、变异测试、随机化隐藏测试）可以同时服务形式化验证、进化搜索和 RLVR，影响面最大 |
| **等算力下的公平比较** | 进化搜索 #1，持续学习 #1 | 两个领域都面临"增益是不是只来自更多算力"的质疑。统一的预算记账和多种子统计协议是低算力、高引用的工作 |
| **状态的分叉、快照与复用** | 智能体基础设施（RL rollout 分叉），进化搜索（种群分叉），持续学习（每用户的权重状态） | 系统层的同一个原语：从同一状态廉价地分叉出成百上千个副本（沙箱快照、前缀 KV 共享、LoRA 状态） |
| **经验写进权重，还是留在外部记忆** | 持续学习 #7，智能体基础设施 #8 | 智能体的记忆可以有三层：KV、文本、权重。何时放在哪一层，需要一个统一的成本模型 |

**推荐的组合**（按背景）：
- **PL / 形式化方法背景**：主攻可验证代码，辅修进化搜索。可以从"评估器审计"这个交叉点进入，一套方法、两个领域都有发表空间。
- **ML 背景、算力有限**：主攻持续学习 / TTT，辅修进化搜索。从"等算力公平评测"进入。
- **系统背景**：主攻智能体基础设施，辅修持续学习。可以从"状态分叉与快照"或"记忆三层模型"进入。
